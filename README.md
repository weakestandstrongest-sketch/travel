# 旅のしおり — 行きたい場所から旅程を自動で組み立てる

行きたい場所を追加して「旅程をつくる」を押すと、日ごとの回る順番と時刻つきの行程を組み立てます。
**のりかえ** で実際の電車を調べて時刻を合わせ、できた旅程は **ひび手帳** の予定として取り込めます。

## Web で使う

`https://weakestandstrongest-sketch.github.io/travel/` で開きます（下の「公開方法」を一度だけ行ってください）。

1. 出発日・日数・宿を決める
2. 行きたい場所を追加する
   - **宿のまわりのおすすめ**：宿を決めると、まわりの観光地（神社・お寺、城・史跡、博物館、公園・景色、テーマパークなど）を有名な順に出します。
     範囲（徒歩圏 2km／近場 10km／遠出 30km／電車で1時間 50km）と種類で絞って、「＋ 追加」で選ぶだけ。滞在時間の目安と、分かる場合は営業時間も入ります
   - 宿の「最寄り駅」を入れると、その駅を起点におすすめと移動時間を考えます
   - **名前で探す**：決まっている場所はここから
   - ★で「必ず行きたい」。「くわしく」で営業時間・行く日・最寄り駅を変えられます
3. 「旅程をつくる」→ 地図と日ごとのタイムラインが出る
4. 「.ics を保存」→ ひび手帳の **設定 → .ics ファイルを読み込む** で選ぶ

入力と最後につくった旅程は、その端末のブラウザに保存されます。

### のりかえ との連携

- 旅程をつくると、電車・バスの区間ごとに のりかえ の `/api/search` で実際の電車を調べ、到着時刻に合わせて後ろの予定を組み直します。
  タイムラインには、乗る駅・乗り換える駅・降りる駅の着／発時刻、乗る電車と番線、途中の駅（開くと時刻つきで一覧）が出ます。
  営業時間や宿に戻る時刻に間に合わなくなったら警告を出します。調べられなかった区間は概算のままです。
- 各区間の「のりかえ」リンクで、その区間・出発時刻の検索結果を のりかえ で開けます。
- のりかえ は `*.github.io` からの呼び出しだけを許可しているので、この旅行アプリも GitHub Pages で公開して使います
  （ローカルの `npm run dev` は localhost なので呼び出せます）。
- 乗換案内では、場所に「最寄り駅」を入れていればその駅名、なければ場所の名前で検索します。
  見つからない区間が出たら、最寄り駅を入れてください。
- のりかえ の URL は画面下の「設定」で変えられます（既定は ひび手帳 と同じ `https://norikae.gohanoishi.workers.dev`）。

### ひび手帳 との連携

- `.ics` には、観光の予定と、電車などの移動の予定（`京都 → 稲荷` のように のりかえ と同じ形のタイトル）が入ります。
- 移動の予定のメモには、乗る電車・番線・乗り換え・運賃と、のりかえ で開くリンクが入ります。
- 予定の UID は内容から決まるので、同じ旅程を2回読み込んでも重複しません（旅程を変えて読み込むと、変わった予定だけ増えます）。

### 公開方法（GitHub Pages・最初の1回だけ）

1. このリポジトリの **Settings → Pages** で、Source を **GitHub Actions** にする
2. 変更を `main` にマージする（プッシュするとテスト → ビルド → 公開が自動で走ります）
3. `https://weakestandstrongest-sketch.github.io/travel/` を iPhone の Safari で開き、共有 →「ホーム画面に追加」

## 開発

```bash
npm install
npm run dev        # http://localhost:5173 で画面を開く
npm test           # テスト
npm run typecheck
npm run build      # dist/ に書き出し
```

コマンドでも使えます（JSON の旅行ファイルから旅程を出力）:

```bash
npm run plan -- examples/kyoto.json                                   # Markdown で表示
npm run plan -- examples/kyoto.json --format ics --out trip.ics       # .ics に書き出し
npm run plan -- examples/kyoto.json --norikae https://norikae.gohanoishi.workers.dev   # 実際の電車に合わせる
```

## 入力ファイル（コマンド用）

```jsonc
{
  "startDate": "2026-11-21",   // 初日
  "days": 2,
  "dayStart": "09:00",         // 宿を出る時刻（既定 09:00）
  "dayEnd": "19:00",           // 宿に戻るリミット（既定 19:00）
  "mode": "transit",           // transit | walk | car
  "base": { "name": "京都駅", "station": "京都", "lat": 34.9858, "lng": 135.7588 },
  "spots": [
    {
      "name": "清水寺",
      "station": "清水五条",    // 任意。乗換案内はこの駅名で検索する
      "lat": 34.9949, "lng": 135.785,  // 省略すると名前から自動で調べる
      "stayMinutes": 90,
      "open": "06:00", "close": "18:00", // 任意
      "priority": "must",       // must | want（既定 want）
      "day": 1                  // 任意。この日に行きたい
    }
  ]
}
```

`lat` / `lng` を省略した場所は OpenStreetMap（Nominatim）で名前から座標を調べます
（1秒に1件ずつ問い合わせるので、件数が多いと少し時間がかかります）。

## しくみ

```
場所の検索 ─▶ プランナー（概算で順番を決める） ─▶ のりかえ で実際の電車に合わせる ─▶ 画面 / .ics / テキスト
web/places    src/core/planner                    src/core/transit                    web/main, src/export
              （所要時間の概算 src/providers/estimator） （src/providers/norikae）
```

- `web/` … 画面（Vite）。地図は国土地理院の淡色地図、場所の検索は OpenStreetMap（見つからなければ国土地理院の地名検索）
- `src/core/` … 旅程を組む中心部分（画面にもコマンドにも依存しない）
- `src/providers/` … 所要時間の概算、場所の検索（コマンド用）、のりかえ、おすすめ（OpenStreetMap の Overpass API と Wikipedia）
- `src/export/` … .ics / Markdown / リンク

プランナー（`src/core/planner.ts`）はヒューリスティックで行程を組みます。

1. 各日について「日付指定 → must → want」の順に場所を入れていく
2. その日の最初の1件は宿から最も遠い場所（同じ方面の場所が同じ日にまとまりやすい）
3. 以降は「宿に戻る時刻が一番早くなる位置」に1件ずつ挿入（営業時間・帰着リミットを守れない挿入は採用しない）
4. 最終日以外は、残りの滞在時間を残り日数で均した量に達したらその日を締める（初日に詰め込みすぎない）
5. 最後に 2-opt で訪問順を改善
6. 入りきらなかった場所は理由つきで「入らなかった場所」に出す

順番を決めるときの移動時間は **直線距離からの概算**（`StraightLineEstimator`）です。
近距離は徒歩、それ以上は電車・バス（固定ロス12分 + 10kmまでは時速25km、その先は快速などで時速55km）として計算します。
順番が決まったあと、のりかえ で実際の電車を調べて時刻を合わせます（順番は変えません）。
